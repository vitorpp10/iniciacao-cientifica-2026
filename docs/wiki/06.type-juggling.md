# Type Juggling

O PHP é uma linguagem dinamicamente tipada. Internamente o motor não enxerga apenas o valor, mas sim a zval que carrega o tipo de dado da variável (`IS_LONG`, `IS_STRING` etc).

A linguagem lida constantemente com dados que trafegam como texto. Quando um usuário preenche um formulário HTML com o número 100, o PHP recebe a string `"100"` (`IS_STRING`), e não um inteiro. Para que o desenvolvedor não precise converter esses dados manualmente a todo momento, a Zend Engine implementa o mecanismo chamado **Type Juggling**.

O Type Juggling é a capacidade do motor do PHP de reinterpretar temporariamente o valor de um zval como se fosse de outro tipo, baseando-se no contexto da operação (como operadores matemáticos `+`, `-`, ou comparativos `==`).

Exemplo, se fizermos a operação `$a = "100" + 20;`, o operador de soma cria um contexto numérico. O PHP automaticamente inspeciona a string `"100"`, converte seu valor para número durante o cálculo, e retorna `120`. O detalhe é que a variável original não sofre mutação definitiva: `$a` continuará sendo do tipo string após a operação.

## Fast Path vs Slow Path

Embora o Type Juggling seja excelente para a produtividade na web, ele introduz um custo de performance (overhead) que se torna custoso em tarefas de processamento massivo.

Quando a Zend Engine realiza uma operação entre tipos idênticos, como `100 + 20`, ela identifica o par `IS_LONG + IS_LONG`. Isso se chama **fast path** (caminho rápido), ou seja, executa diretamente da CPU de forma quase instantânea.

No entanto, quando fazemos `"100" + 20`, o motor se depara com a combinação `IS_STRING + IS_LONG`. Como esse par não é suportado pelo fast path, o PHP muda a execução para **slow path** (caminho lento). Para resolver esta conta o motor:

- Inspeciona os caracteres da string para verificar se ela é uma *numeric string* válida.
- Fazer o parse para determinar se ela deve se transformar em um número inteiro (`int`) ou decimal (`float`).
- Criar a representação convertida na memória.
- Realizar a operação matemática final.

Em um loop (`for`) por exemplo, o acúmulo de verificações de tipo, desvios lógicos (branches) e parsing de strings piora a performance da aplicação. É exatamente nesse gargalo que extensões em C++ aumentam o desempenho. Elas extraem os tipos nativos diretamente do zval uma única vez, transferindo a matemática para a linguagem compilada e ignorando validações repetitivas da Zend Engine.

## Contexto Comparativo e Coerção

No PHP, a forma como você compara dois zvals define o nível de trabalho que a Zend Engine terá que realizar. O motor oferece dois operadores com comportamento estruturalmente diferentes:

**`==` (Igualdade Frouxa)**: Permite a coerção de tipos. O motor avalia se os valores base são equivalentes, independentemente de como estão escritos ou de qual seu tipo original. Para que isso funcione, o PHP faz o Type Juggling por baixo dos panos.

**`===` (Identidade estrita)**: Exige igualdade tanto do valor quanto do tipo. O motor não realiza coerção e se os tipos `zvals` forem diferentes, a avaliação falha instantaneamente no `fast path`, poupando ciclos de CPU.

A Zend Engine não aplica uma regra universal como por exemplo "converta tudo para número". O tipo para o qual um valor será interpretado depende da operação e do outro operando.

A presença de um booleano muda a regra: se um dos operandos for `bool` ou `null`, o PHP interpretará os dois lados como booleanos antes de comparar.

Veja a diferença de comportamento do mesmo valor `"50"` dependendo do contexto:

Contexto numérico (`+`):

``` 
"50" + 10
↓
"50" (IS_STRING) → interpretado como número → 50
50 + 10 = 60
``` 

Contexto Comparativo Booleano (`==`):

```
"50" == true
↓
"50" (IS_STRING) → interpretado como bool → true
true == true
```

Neste segundo caso, como um dos lados é `true`, a string `"50"` não virou o número 50, ela virou o booleano `true`.

### Truthiness

Esse comportamento nos leva ao conceito de **Truthiness**, ou seja, como a Zend Engine interpreta o "grau" de um valor quando ele é colocado em um contexto booleano (como `if`, `while`, `!`, `&&`, `||`, ou condição ternária).

No PHP, a regra para strings em contextos booleanos é rigorosa: uma string será considerada `false` apenas se for vazia `""` ou for exatamente a string `"0"`.

Valores interpretados como `false` (Falsy):

- `false`
- `0` (int) e `0.0` (float)
- `""` (string vazia)
- `"0"` (string zero)
- `null`
- `[]` (array vazio)

Valores interpretados como `true` (Truthy):

Qualquer outra string com tamanho maior que zero é verdadeira:

- `"abc"` → `true`
- `"1"` → `true`
- `"50"` → `true`
- `"false"` → `true`


### Avaliação de Expressões

Além da conversão de tipos, a Zend Engine otimiza a forma como as expressões lógicas e matemáticas são avaliadas em tempo de execução. Compreender esses mecanismos é essencial para entender o comportamento do código.

#### Short-Circuit Evaluation (Avaliação de Curto-Circuito)

O short-circuit é um mecanismo de otimização onde a avaliação de uma expressão lógica é interrompida assim que o resultado final já pode ser determinado pelos operandos iniciais. O restante da expressão simplesmente não é executado, poupando processamento.

Regras de interrupção visual:

Operador `&&` (AND):

- `false` na esquerda → PARA (O resultado já é obrigatoriamente falso).
- `true` na esquerda → Precisa avaliar o lado direito.

Operador `||` (OR):

- `true` na esquerda → PARA (O resultado já é obrigatoriamente verdadeiro).
- `false` na esquerda → Precisa avaliar o lado direito.

#### Pré-incremento versus Pós-incremento

A ordem de avaliação também afeta operadores matemáticos, gerando resultados diferentes no momento da leitura da variável pelo motor:

**Pós-incremento (`$x++`)**: Retorna o valor antigo para a expressão atual e, logo em seguida, incrementa a variável.

**Pré-incremento (`++$x`)**: Incrementa a variável primeiro e já retorna o valor novo atualizado para a expressão.

#### Coerção implícita vs Conversão Explícita (Casting)

Para ter previsibilidade, é crucial separar oque o motor faz por conta própria do que o user declara no código:

**Coerção Implícita (Type Juggling)**: O PHP decide converter o tipo temporariamente devido ao contexto da operação.

```php
// Coerção Implícita
// Não pedimos para o PHP transformar em inteiro, as regras numéricas do '+' forçaram isso.
$resultado = "50" + 10; 
```

**Conversão Explícita (Casting)**: O user solicita diretamente e explicitamente a conversão do valor, mudando a forma como ele será lido na memória.

```php
// Conversão Explícita
$x = "50";
$y = (int) $x; // O desenvolvedor forçou a string a se tornar um inteiro em $y.
```

#### strict_types e Declarações de Retorno

Em aplicações modernas, depender do Type Juggling pode ocultar bugs. Para melhorar o código contra coerções indesejadas, o PHP introduziu mecanismos de defesa nas assinaturas das funções.

A diretiva `strict_types=1`:

Quando declarada no topo de um arquivo, ela desabilita grande parte das coerções automáticas (implícitas) de tipos escalares. Se uma função espera um `int` e você passar uma string numérica (`"50"`), a Zend Engine não fará o Type Juggling. Em vez disso, a incompatibilidade de tipos gerará um erro fatal instantâneo chamado de `TypeError`.

Type Declarations (Parâmetros e Retorno):

As declarações de tipo atuam como "fronteiras alfandegárias" da função. Elas dizem exatamente o que deve entrar e o que deve sair. Ao definir um retorno, você garante que "o valor que atravessar esta fronteira de saída satisfaz obrigatoriamente este tipo" (seja de forma nativa ou por coerção permitida, caso `strict_types` esteja desativado).

Visualizando a Fronteira:

```
function calcular(int $x): float
                 ↑        ↑
                 │        └─ "O que deve SAIR?"
                 └────────── "O que deve ENTRAR?"
```
